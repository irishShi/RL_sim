## 项目整体说明（RL_sim）

### 1. 项目做什么

本项目是一个**铁路/高速移动场景下的蜂窝切换（Handover, HO）策略仿真 + 强化学习训练**工程，核心目标是：

- 在一条 1D 轨道上模拟列车从基站 A 覆盖区驶向基站 B 覆盖区的过程
- 用信道模型生成随位置变化的 **RSRP / SINR**
- 通过切换逻辑（A3 事件 + TTT + 保护窗口 + 切换中断）决定是否切换服务小区
- 用 **Rainbow DQN（C51 + Dueling + Double + Noisy + PER + N-step）**学习“选择 Hys/TTT 参数”的策略
- 支持**离线学习**：先收集数据集，再离线训练（可选 CQL 正则化），并与传统 A3 固定参数策略做对比评测

---

### 2. 两条核心工作流（你跑项目时会用到的链路）

#### 2.1 离线学习链路（推荐）

- **数据收集**：`collect_data.py`
  - 与环境交互，按指定策略（随机 / 均匀混合 / 固定参数等）采样轨迹
  - 维护时序窗口（`ObservationWindow`）并在每步构造训练所需的 15×10 输入
  - 用 `NStepBuffer` 把单步转成 N-step 经验
  - 输出 `data/*.npz` 数据集

- **离线训练**：`train_rainbow_offline.py`
  - `OfflineDataset` 读入 `npz`
  - 把样本灌进 `ReplayBuffer`（作为“可 PER 采样的离线经验池”）
  - 训练 `RainbowWithForecast`（可选 `--use_cql`）
  - 周期性保存 `checkpoints/rainbow_offline_epoch_*.pth`，最终保存 `checkpoints/rainbow_offline_final.pth`

- **评测对比**：`test_simple.py` / `test_batch_comparison.py`
  - `ScenarioGenerator` 生成并固化场景，确保不同策略在同一场景对比
  - 对比：传统 A3 固定 (Hys, TTT) vs 离线训练 RL 模型
  - 输出对比图：`test_comparison.png`、`batch_comparison.png`、`batch_comparison_boxplot.png`

#### 2.2 在线训练链路（与环境实时交互）

- **在线训练**：`train_rainbow.py`
  - 与环境交互采样经验
  - `ReplayBuffer + NStepBuffer + project_distribution(C51)` 完成 Rainbow 更新
  - 输出 `checkpoints/rainbow_episode_*.pth` 与 `checkpoints/rainbow_final.pth`

> 说明：在线训练脚本里用的是 `online_net.act(..., epsilon=0.0)`（NoisyNet 本身提供探索），`get_epsilon()` 函数更多是保留接口。

### 3. 环境（仿真）侧：各模块职责

#### 3.1 `envs/train_ho_env.py`：主环境 `TrainHandoverEnv`

这是项目的仿真核心，职责包括：

- **接口**：实现 Gymnasium `Env` 的 `reset()` / `step()`，用于训练/评测驱动
- **动作空间**：
  - 默认启用 `use_hys_ttt=true`：动作是 **48 个离散动作**，每个动作映射到一组 (Hys, TTT)
  - 兼容模式 `use_hys_ttt=false`：动作是 2 个（不切换/切换）
- **子模块编排**：
  - `WeatherModel`：采样温度/湿度/PM2.5，并提供天气额外损耗
  - `ChannelModel`：按位置计算路径损耗、阴影衰落、（可选）快衰落，输出 RSRP/SINR
  - `HandoverLogic`：实现 A3 事件判决、TTT 计时、保护时间/距离（TTS）、切换执行与 outage 判定
- **切换中断**：切换发生后模拟短时通信中断（用极差的 SINR/RSRP 覆盖该时隙）
- **Outage/RLF 统计**：outage 既可能来自 SINR 过低，也可能来自切换中断期间
- **KPI 统计**：切换次数、outage 占比/事件数、SINR 分位数、乒乓切换等（episode 结束时在 `info["kpis"]` 给出）
- **输出 `info`**：每步返回大量调试/训练辅助字段，如：
  - `rsrp_serv_dbm / rsrp_neig_dbm / sinr_serv_db`
  - `delta_rsrp_dbm`
  - `current_hys / current_ttt`（在 48 动作模式下）
  - `ho_executed / in_interruption / outage` 等

#### 3.2 `envs/channel_model.py`：信道模型 `ChannelModel`

- **路径损耗**：对数距离模型 \(PL0 + 10n\log10(d)\)
- **阴影衰落**：
  - 默认：距离相关 AR(1) 模型（相关距离 `shadow_corr_distance_m`）
  - 若使用场景数据：从 `ScenarioGenerator` 预生成序列插值读取，保证策略对比公平
- **天气损耗**：调用 `WeatherModel.compute_weather_loss_db()`
- **同频干扰**：
  - 动态模式（默认）：A 的干扰来自 B 的信号功率，B 的干扰来自 A 的信号功率
  - 可选叠加额外干扰源
- **输出**：`compute_link_metrics(x)` 返回 `rsrp_A, rsrp_B, sinr_A_db, sinr_B_db`

#### 3.3 `envs/ho_logic.py`：切换逻辑 `HandoverLogic`

- **参数状态**：当前 `Hys`、`TTT`，以及 A3 条件是否满足、TTT 计时器
- **A3+TTT 判决**：当 \(\Delta RSRP = RSRP_{neig}-RSRP_{serv} > Hys\) 持续超过 `TTT` 才触发切换
- **保护窗口（TTS）**：支持按时间或按距离的切换保护，避免频繁切换
- **outage 判定**：`sinr_serv < sinr_outage_db`

#### 3.4 `envs/weather_model.py`：天气模型 `WeatherModel`

- 采样温度/湿度/PM2.5
- 计算天气引起的额外损耗（线性组合）
- 将天气参数归一化到 [0,1] 作为观测特征的一部分

#### 3.5 `envs/handover_wrapper.py`：包装器 `HandoverWrapper`（可选）

该包装器把“48 动作（Hys/TTT）→ 2 动作（切/不切）”的逻辑放在 wrapper 里实现。

但需要注意：`TrainHandoverEnv` 目前**已经原生支持 48 动作 + A3/TTT**，因此 wrapper 更多是：

- 用于对接“旧环境只支持 2 动作”的历史方案
- 或者用于把参数更新与切换触发拆分成两层（环境只接收切换动作）

### 4. 强化学习侧：模型、观测、回放、算法职责

#### 4.1 `models/rainbow_model.py`：`RainbowWithForecast`

实现了“时序 + 分布式价值 + 辅助预测”的联合模型：

- **输入**：窗口观测 `x`，形状 `[B, N, F]`（默认 \(N=15\), \(F=10\)）
- **时序编码器**：`TemporalEncoderGRU` 把序列编码成 `[B, H]`
- **共享特征层**：`SharedFeatureNet` 得到 `[B, D]`
- **Rainbow 头**：`RainbowHead`
  - **Dueling**：V stream + A stream
  - **C51**：输出每个动作的价值分布 `[B, A, num_atoms]`
  - **NoisyLinear（可选）**：在线训练时用于探索；离线训练默认关闭
- **辅助预测头**：`ForecastHead` 预测下一步 `ΔRSRP` 的监督信号（回放中存的是 `delta_rsrp_target`，通常归一化到 [0,1]）

#### 4.2 `models/action_space.py`：`ActionSpace`

- 定义 48 个动作的离散集合：8 个 Hys × 6 个 TTT
- 提供 `action_to_hys_ttt()` 与 `hys_ttt_to_action()` 映射

#### 4.3 `models/observation_builder.py`：`ObservationWindow`

维护时序窗口并构造模型输入特征（默认 10 维/步）：

- 来自环境观测的：`RSRP_serv_norm`、`RSRP_neig_norm`、`SINR_serv_norm`、`pos_norm`、`T_norm` 等
- 扩展特征：
  - `ΔRSRP_norm`（由 `info['rsrp_*_dbm']` 计算）
  - `v_norm`
  - `time_since_last_ho_norm`
  - `Hys_norm`、`TTT_norm`（来自当前策略参数）

> 注意：环境本身观测是 7 维；训练/推理时模型实际吃的是窗口化后的 10 维特征。

#### 4.4 `utils/replay_buffer.py`

- `ReplayBuffer`：以 numpy 数组存储经验，支持 **PER 采样**（`priorities` + IS weights）
- `NStepBuffer`：把单步经验聚合成 N-step return（`reward` 字段存的是 N-step 累积回报）

#### 4.5 `utils/c51_projection.py`

- `project_distribution(...)`：C51 的 Bellman 目标分布投影到固定 support 上

#### 4.6 `utils/dataset_loader.py`

- `OfflineDataset`：加载 `collect_data.py` 生成的 `.npz` 数据集
- 对关键数组形状做 assert，并打印动作分布/平均奖励/完成率等统计

#### 4.7 `utils/scenario_generator.py`

用于“公平对比”：在评测时生成确定性场景，并可保存/加载：

- 速度、天气（温/湿/PM2.5）
- 位置网格上的阴影衰落序列（A/B 各一条，AR(1) 相关）
- 环境 `reset(..., options={"scenario_data": ...})` 会使用这些数据，保证策略间对比的一致性

### 5. 入口脚本与它们负责的事情

- **`collect_data.py`**
  - 负责离线数据收集与保存（`data/*.npz`）
  - 支持 `random / fixed / uniform_mix` 等策略生成动作覆盖

- **`train_rainbow_offline.py`**
  - 负责离线训练（支持 `--use_cql`）
  - 训练单位为 epoch；每个 epoch 从回放池采样 `samples_per_epoch` 条样本

- **`train_rainbow.py`**
  - 负责在线训练（与环境交互采样、边采边学）
  - PER + N-step + C51 投影 + target network 更新

- **`test_simple.py`**
  - 单场景对比：传统 A3 固定参数 vs 离线 RL 模型
  - 输出对比曲线图（含切换点与 RL 选的参数标注）

- **`test_batch_comparison.py`**
  - 多场景批量对比：多个 A3 参数组 + RL
  - 输出 KPI 柱状图与箱线图

### 6. 配置与产物（你改参数时主要看这里）

#### 6.1 环境配置 `configs/default_env_config.yaml`

常改项：

- **动作模式**：`use_hys_ttt`（48 动作 vs 2 动作兼容）
- **信道/干扰**：路径损耗、阴影、动态干扰、噪声、快衰落开关
- **切换机制**：`TTS_mode`、`T_guard_s` / `T_guard_m`、`ttt_quantize_to_50ms`
- **outage**：`sinr_outage_db`、`T_out_s`
- **奖励**：`reward_type`（R0/R1/R2）、`lambda_ho`、`lambda_out`
- **中断**：`ho_interruption_slots`、`ho_interruption_sinr_db`、`ho_interruption_rsrp_dbm`

#### 6.2 模型与训练配置 `configs/model_config.yaml`

- **动作集合**：`hys_set / ttt_set / num_actions`
- **窗口与特征**：`window_size / obs_dim`
- **网络**：GRU hidden、共享层维度、C51 原子数、\(v_{min}/v_{max}\)、Noisy 初始化
- **训练超参**：batch、lr、gamma、n_steps、PER alpha/beta、target 更新频率、梯度裁剪、aux 权重 `lambda_aux`

#### 6.3 训练/评测产物

- **模型**：`checkpoints/*.pth`
- **数据集**：`data/*.npz`
- **场景**：`scenarios/*.pkl`（评测时可复用）
- **图表**：`test_comparison.png`、`batch_comparison.png`、`batch_comparison_boxplot.png`

---

### 7. 一句话总结“各目录干什么”

- **`envs/`**：仿真环境与物理/协议层逻辑（天气、信道、切换规则、KPI）
- **`models/`**：RL 模型结构（GRU+Rainbow+C51+Noisy）与动作/观测构建工具
- **`utils/`**：训练基础设施（回放池、N-step、C51 投影、离线数据集、场景生成）
- **`configs/`**：环境与模型训练参数
- **`checkpoints/`**：训练输出的模型权重（不建议纳入代码版本管理）
- **`data/`**：离线学习数据集与（可选）真实数据相关脚本
- **`docs/`**：使用指南、优化记录、以及本总览文档

---

### 8. （可选）真实数据与可视化脚本

- **`data/real_data/file_reader.py`**：读取并可视化现场 Excel（`nr_info.xlsx`）里的 RSRP 数据，支持按基站/PCI 分离绘图与滑块缩放。
- **`data/real_data/validate_model.py`**：把现场数据加工成模型输入窗口，加载训练好的模型做推理，输出预测误差与图表/报告（如 `validation_report.txt`）。
- **`plot_rsrp.py`**：用当前环境配置绘制沿轨道的 A/B 小区 RSRP 曲线，便于直观检查参数设置对覆盖的影响。

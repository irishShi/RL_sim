# 高速铁路切换优化的主要目标与算法边界

本文档用于统一说明本项目的核心研究对象、可优化范围和不应由切换算法承担的系统问题。后续训练、评估、论文表述和代码代理修改都应以这里的边界为准。

## 1. 主要目标

本项目研究的是高速铁路蜂窝/5G-R 场景中的 A3 切换参数自适应问题：

> 在列车高速穿越相邻小区重叠区时，根据实时无线观测动态选择 A3 的 `Hys` 和 `TTT`，在降低晚切、过早切、乒乓切换、切换中断和 outage 之间取得平衡。

当前主线算法是 `Obs7 + GRU + Rainbow DQN`：

- 输入为最近 15 步、每步 7 维观测：`RSRP_serv`、`RSRP_neig`、`Delta RSRP`、`SINR_serv`、速度、位置、距上次切换时间。
- 输出为 48 个离散 `(Hys, TTT)` 动作之一。
- 环境仍由 A3 事件、TTT timer、切换保护窗口、中断、outage 和 KPI 逻辑统一执行。
- late handover guard 是部署/导出阶段的轻量安全约束，不是新的大模型。

因此，本项目的核心贡献应聚焦于“切换参数如何随状态自适应变化”。弱覆盖、强干扰、NLOS/fading 等场景可以作为鲁棒性验证对象，但论文表述应强调算法是在可切换条件下缓解退化，而不是泛化成所有无线覆盖、干扰、资源调度或业务拥塞问题的通用解法。

## 2. 切换算法能控制什么

切换算法直接可控的是：

- 是否选择更激进或更保守的 `Hys/TTT`。
- 何时触发 A3 条件并完成 TTT 计时。
- 在邻区逐渐变强时减少晚切。
- 在服务区仍明显占优时减少过早切和乒乓。
- 在切换重叠区内降低不必要切换、中断和 outage 风险。
- 在一定程度的弱覆盖、强干扰、NLOS/fading 下，利用服务区和邻区之间仍存在的质量差异，选择更合适的切换时机。

这些问题可以通过当前模型、R5 奖励、action hold、profile 泛化评估和 late guard 进行实验验证。

## 3. 切换算法不能过度承担什么

以下问题不应被表述为单靠本项目切换算法可以解决：

- 两个候选小区都处于极端弱覆盖，切过去也没有足够 SINR。
- 目标小区不可用或邻区质量同样差。
- NLOS/fading 导致深衰落，且服务区和邻区都没有可利用的质量优势。
- 极强同频干扰、噪声抬升或网络规划导致覆盖空洞，使 A3 参数调整没有有效切换目标。
- 资源不足、重业务排队、RLC/App delay 尾部过大。
- 调度、功控、波束管理、多连接、冗余链路等跨层或网络侧问题。

这些现象可能在 `Stress`、`HighInterference` 或极端弱覆盖 profile 中出现。若退化来自晚切、过早切或乒乓，切换算法应继续优化；若退化来自“相邻基站都不可用”或资源/业务瓶颈，则不应为了少数极端样本盲目增加模型复杂度，不能替代网络覆盖增强、资源调度优化或多链路可靠性设计。

## 4. 复杂度增加的决策原则

新增观测维度、网络模块、reward 项或安全规则前，需要先回答两个问题：

1. 该改动是否针对明确的“切换可控问题”，例如晚切、乒乓、切换区中断或不必要切换？
2. 该改动是否在核心 KPI 上带来稳定收益，并且收益大于模型复杂度、训练数据需求、推理成本和可解释性损失？

如果极端失败样本主要来自相邻候选小区都不可用的覆盖/资源极限，则不宜为了少数场景盲目扩大模型。更推荐的做法是：

- 保持 `Obs7 + GRU + Rainbow DQN` 作为主模型。
- 用 `late guard` 这类轻量、可解释的安全层处理明确的晚切风险。
- 将“切换可缓解”和“切换无法根治”的场景分开写入算法边界和误差分析。
- 只有在多 seed、多 profile 证据充分时，再考虑 `R6 robust reward` 或新增业务/队列观测。

## 5. 核心性能指标

主指标应优先服务于切换优化本身：

- `ho_count` / `ho_per_km`：切换频率。
- `ping_pong_count`：乒乓切换。
- `outage_time_ratio`：断连风险。
- `sinr_p5_db`：尾部无线质量。
- `overlap_zone_sinr_mean_db`：切换区平均 SINR。
- `comm_interruption_ratio_in_overlap_zone`：切换区通信中断率。
- `handover_failure` / `RLF proxy`：若实现，可作为可靠性指标。

辅助指标用于解释效率和部署成本：

- 模型参数量、推理耗时、policy table 大小。
- 训练时间、收敛曲线、reward 曲线。
- Simu5G 中的 CQI、丢包率、App/RLC delay 尾部分位。

论文和实验报告中应避免只用平均 SINR 或单个 Stress 场景判断算法优劣。更合理的表述是：本方法主要优化切换重叠区内的 A3 参数自适应；对弱覆盖、强干扰、NLOS/fading 的中等退化，应验证其缓解晚切和降低中断的能力；对相邻候选基站都不可用或资源本身不可满足的极端工况，则不能保证全面修复。

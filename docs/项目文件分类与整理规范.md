# 项目文件分类与整理规范

本文档用于约束 RL_sim 后续扩展、实验复现和论文写作过程中的文件归属。原则是：源码、数据、实验产物、精选结果、论文材料彼此分离；临时文件只进入 `_inbox/`，不得长期散落在根目录。

## 1. 总体目录

```text
RL_sim/
├─ configs/                  # 环境、模型、实验配置
├─ envs/                     # 仿真环境与信道/切换逻辑
├─ models/                   # 模型结构、动作空间、观测构造
├─ utils/                    # 训练/评估共用工具
├─ scripts/                  # 可执行脚本
│  ├─ train/                 # 训练脚本
│  ├─ eval/                  # 评估脚本
│  ├─ data/                  # 数据清洗、验证、转换脚本
│  └─ plot/                  # 绘图脚本
├─ data/                     # 数据文件，不放论文最终图表
│  ├─ raw/                   # 原始数据，只读保存
│  ├─ processed/             # 清洗后的数据
│  ├─ datasets/              # 离线训练数据集
│  └─ scenarios/             # 固定随机种子的评估场景
├─ experiments/              # 每次实验的完整输出
│  └─ runs/
│     └─ YYYYMMDD_HHMMSS_method_seedXX/
│        ├─ config/          # 本次实验使用的配置快照
│        ├─ checkpoints/     # 模型权重
│        ├─ logs/            # 训练/评估日志
│        ├─ metrics/         # JSON/CSV 指标
│        ├─ figures/         # 本次实验生成的图片
│        ├─ tables/          # 本次实验生成的表格
│        └─ notes.md         # 实验说明
├─ results/                  # 经筛选、准备用于论文分析的阶段性结果
│  ├─ comparison/
│  ├─ ablation/
│  ├─ sensitivity/
│  └─ case_study/
├─ paper/                    # 论文写作工程
│  ├─ manuscript/
│  ├─ assets/
│  │  ├─ figures/source/
│  │  ├─ figures/final/
│  │  ├─ tables/source/
│  │  └─ tables/final/
│  ├─ references/
│  ├─ notes/
│  └─ submission/
├─ docs/                     # 项目技术文档
│  ├─ design/
│  ├─ usage/
│  ├─ experiments/
│  └─ archive/
├─ assets/                   # 项目通用素材
├─ archive/                  # 旧版本、废弃材料、历史备份
└─ _inbox/                   # 临时收纳箱，定期清理
```

## 2. 文件归属规则

1. 根目录只保留项目入口说明、依赖文件、仓库配置和一级目录，不再直接放实验图片、指标 JSON、模型权重或临时脚本。
2. 训练、评估、绘图、数据处理脚本统一放入 `scripts/` 的对应子目录。
3. 离线训练数据集放入 `data/datasets/`，真实原始数据放入 `data/raw/real/`，清洗后的真实数据放入 `data/processed/real/`。
4. 固定随机种子生成的评估场景放入 `data/scenarios/`。
5. 每一次训练或评估的完整输出放入 `experiments/runs/<run_id>/`，其中 `<run_id>` 推荐使用 `YYYYMMDD_HHMMSS_method_seedXX`。
6. `results/` 只保存经过筛选、准备进入论文分析的结果，不保存全部中间产物。
7. 论文正文、论文插图、论文表格、参考文献和投稿材料全部放入 `paper/`。
8. 技术说明、运行指南、设计说明和实验记录放入 `docs/`，不要和论文草稿混放。
9. 一时无法分类的文件可以先放 `_inbox/`，但必须在阶段性整理时迁出或删除。

## 3. 命名规则

实验目录：

```text
YYYYMMDD_HHMMSS_rainbow_cql_seed2026
YYYYMMDD_HHMMSS_a3_grid_eval_seed10000
```

论文图：

```text
fig01_system_model.svg
fig02_training_curve.pdf
fig03_policy_comparison.png
fig04_ablation_reward.pdf
```

论文表：

```text
tab01_hyperparameters.tex
tab02_comparison_results.csv
tab03_ablation_study.tex
```

数据集：

```text
offline_dataset_<policy>_<episodes>ep_seed<start>.npz
real_trace_processed_<date>.csv
scenario_seed_<seed>.pkl
```

## 4. 实验输出规范

训练脚本默认应写入：

```text
experiments/runs/<run_id>/checkpoints/
experiments/runs/<run_id>/logs/
experiments/runs/<run_id>/metrics/
```

评估脚本默认应写入：

```text
experiments/runs/<run_id>/metrics/
experiments/runs/<run_id>/figures/
```

论文最终使用的图表再从 `experiments/` 或 `results/` 中筛选、加工、复制到：

```text
paper/assets/figures/final/
paper/assets/tables/final/
```

## 5. Git 管理建议

建议纳入版本管理：

- 源码、配置、脚本、README、技术文档、论文草稿。
- 小型示例配置和必要的轻量样例数据。
- 论文最终图表可以纳入，但大型中间图片不建议纳入。

建议忽略：

- `.venv/`、`__pycache__/`、`.pyc`。
- `experiments/runs/` 中的大量 checkpoint、日志和中间图。
- `data/raw/`、`data/processed/`、`data/datasets/` 中的大型数据。
- `_inbox/` 中的临时文件。

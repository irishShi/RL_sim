# Simu5G 复杂铁路切换场景扩展方案

本文档记录在当前 3 km 双基站铁路切换场景基础上，进一步扩展复杂实验场景的方案。当前目标不是立刻搭建一个全新的大规模铁路网，而是在已经跑通的 `railway_handover` 场景上逐步增加无线环境、覆盖、干扰和业务压力，先验证固定 A3 与 RL 查表策略在复杂条件下的差异。

## 1. 当前基础场景

基础场景保持项目设定：

- 线路长度：3 km。
- 基站布局：线路两端各一个 gNB，约 3 km 站间距。
- 车辆速度：300 km/h。
- 业务方向：下行 CBR。
- 对比策略：
  - `FixedA3`：固定 A3+TTT，`Hys=3 dB`，`TTT=160 ms`。
  - `RLTable`：Simu5G 每 50 ms 根据当前观测查 `policy_table.csv`，动态选择 `Hys/TTT`。

目前 RL 查表策略仍是离线桥接方案，不等价于 Simu5G 内实时训练。它的意义是把已有 Rainbow DQN 策略嵌入更真实的事件仿真环境，先检查策略迁移后的动作趋势和 KPI 表现。

## 2. 第一阶段：单因素压力场景

第一阶段保留 3 km 双 gNB 拓扑，只改变无线和业务条件。这样可以避免把问题一次性扩大到“拓扑、信道、业务、算法”全部耦合，方便定位 RL 策略在什么因素下失效。

| 场景 | 作用 | 主要配置 |
| --- | --- | --- |
| `TrackOffset` | 基础铁路偏置场景 | gNB 与轨道横向距离约 150 m |
| `WeakCoverage` | 弱覆盖 | 降低发射功率、站高和天线增益 |
| `HighNoise` | 高接收噪声 | 提高热噪声和 UE 噪声系数 |
| `NlosFading` | 非视距与快衰落 | 开启 shadowing、Rayleigh fading、NLOS |
| `HighInterference` | 强小区间干扰 | 开启上下行、背景和外部干扰，降低可用 RB |
| `HeavyTraffic` | 高业务压力 | 增大发包频率和包大小 |
| `Stress` | 综合压力 | 叠加 NLOS、弱覆盖、高噪声、低资源和重业务 |

每个场景运行两种策略：

- `Railway-300-DL-<Scene>-FixedA3`
- `Railway-300-DL-<Scene>-RLTable`

第一轮矩阵共 `7 个场景 x 2 种策略 = 14 次仿真`。

## 3. 第二阶段：速度敏感性

在第一阶段跑通后，再引入速度维度，例如：

- 200 km/h：中高速，切换窗口更宽。
- 300 km/h：当前主场景。
- 350 km/h：典型高速铁路压力。
- 400 km/h：更极限的高速压力。

速度敏感性建议先只在 `TrackOffset`、`NlosFading`、`Stress` 三类场景上跑，避免组合爆炸。

## 4. 第三阶段：连续多切换走廊

当双 gNB 单次切换已经稳定后，再扩展为 9 km 或 12 km 连续走廊：

- 4 到 5 个 gNB 沿线布置。
- 相邻站间距约 3 km。
- UE/列车连续穿越多个小区。
- 重点观察 ping-pong、过早切换、过晚切换、连续切换后恢复时间。

这一阶段需要新增 NED 拓扑或复制多小区网络模块，不建议和第一轮压力矩阵同时做。

## 5. 重点 KPI

每轮仿真至少提取以下指标：

- 切换行为：切换次数、首次切换时间、首次切换位置。
- 无线质量：RSRP serving/neighbor、Delta RSRP、SINR、CQI。
- 业务质量：丢包率、应用层时延、RLC 时延、MAC 时延、RLC 吞吐。
- RL 策略行为：action、Hys、TTT、Q 值均值和时间序列。
- 切换窗口局部图：首次切换前后若干秒内的 RSRP、SINR/CQI、时延峰值。

判断 RL 是否有效时，不只看“是否少切换”，还要看是否用更合适的 Hys/TTT 把切换点推到更合理的位置，并避免切换附近 SINR/CQI 大幅下降或应用层时延尖峰。

## 6. 当前执行计划

本轮先执行第一阶段复杂矩阵：

1. 在 Simu5G `railway_handover/omnetpp.ini` 中补充 `场景 x 策略` 配置。
2. 新增批量运行脚本，自动跑 14 个配置并复制 `.sca/.vec/.vci` 到本项目。
3. 新增复杂矩阵分析脚本，自动生成每个配置的摘要、时序图、切换窗口图。
4. 汇总 FixedA3 与 RLTable 在每个压力场景下的 KPI 差异。

第一轮结果只是迁移验证，不直接作为最终论文结论。若 RLTable 在 `Stress` 或 `NlosFading` 下表现明显异常，下一步应回到策略表生成阶段，增加 Simu5G 风格观测扰动、更多信道压力样本，或改成在线交互式策略接口。

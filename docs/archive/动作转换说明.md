# 动作转换说明：Hys/TTT → 切换决策

## 一、问题背景

### 1.1 原始环境的动作空间

原始环境 `TrainHandoverEnv` 只支持 **2 个简单动作**：

```python
# 原始环境的动作空间
self.action_space = spaces.Discrete(2)
# 0 = 不切换
# 1 = 切换
```

这意味着环境只能接收"切换"或"不切换"的指令，无法设置切换参数。

### 1.2 模型的动作空间

但我们的 Rainbow DQN 模型需要输出 **48 个动作**，每个动作代表一个 **(Hys, TTT) 参数组合**：

```python
# 模型的动作空间
Hys_set = [1.5, 2.0, 2.5, 3.0, 3.5, 4.0, 4.5, 5.0]  # 8个
TTT_set = [0, 40, 80, 160, 320, 640]  # 6个
总动作数 = 8 × 6 = 48
```

例如：
- 动作 0 → (Hys=1.5, TTT=0)
- 动作 10 → (Hys=2.0, TTT=160)
- 动作 47 → (Hys=5.0, TTT=640)

### 1.3 问题

**模型输出的是参数组合（Hys/TTT），但环境只能接收切换指令（0/1）**

因此需要一个"转换层"，将参数组合转换为切换决策。

---

## 二、转换逻辑

### 2.1 标准切换算法（A3 事件 + TTT）

在 5G/LTE 中，切换决策遵循以下规则：

1. **A3 事件条件**：`RSRP_neig - RSRP_serv > Hys`
   - 当邻区信号比服务小区信号强 **超过 Hys 阈值** 时，触发 A3 事件
   - Hys（迟滞值）用于避免乒乓切换

2. **TTT（Time-To-Trigger）**：A3 条件需**持续满足 TTT 时间**才执行切换
   - 避免因信号短暂波动导致的频繁切换
   - TTT 单位是毫秒（ms）

### 2.2 转换流程

```
模型输出动作 (0-47)
    ↓
转换为 (Hys, TTT) 参数
    ↓
检查当前 RSRP：RSRP_neig - RSRP_serv > Hys？
    ↓
如果满足 → 启动 TTT 计时器
    ↓
计时器 >= TTT？
    ↓
是 → 执行切换 (env_action=1)
否 → 不切换 (env_action=0)
```

### 2.3 具体示例

假设：
- 模型输出动作 **10** → (Hys=2.0 dB, TTT=160 ms)
- 当前 RSRP：服务小区 = -90 dBm，邻区 = -87 dBm
- ΔRSRP = -87 - (-90) = **3 dB**

**步骤 1**：检查 A3 事件
```
ΔRSRP (3 dB) > Hys (2.0 dB)  ✓ 满足条件
```

**步骤 2**：启动 TTT 计时器
```
如果这是第一次满足条件：
  - 设置 a3_condition_met = True
  - 启动计时器 ttt_timer = 0.05秒（一个时间步）
  
如果条件持续满足：
  - 累积计时器 ttt_timer += 0.05秒
```

**步骤 3**：检查 TTT
```
ttt_timer (0.05秒) >= TTT (0.16秒)？  ✗ 未达到
→ 不切换 (env_action=0)

继续等待，如果条件持续满足：
ttt_timer (0.20秒) >= TTT (0.16秒)？  ✓ 达到
→ 执行切换 (env_action=1)
```

## 三、代码实现解析

### 3.1 关键代码片段

```python
def step(self, action_48: int):
    # 步骤 1：将动作索引转换为 (Hys, TTT)
    hys, ttt = self.action_space.action_to_hys_ttt(action_48)
    # 例如：action_48=10 → hys=2.0, ttt=160
    
    # 步骤 2：获取当前 RSRP 差值
    delta_rsrp = rsrp_neig - rsrp_serv  # 例如：3.0 dB
    
    # 步骤 3：检查 A3 事件条件
    if delta_rsrp > self.current_hys:  # 3.0 > 2.0 → True
        # A3 条件满足，累积 TTT 计时器
        self.a3_condition_met = True
        self.ttt_timer += dt  # dt = 0.05秒（一个时间步）
    else:
        # A3 条件不满足，重置计时器
        self.a3_condition_met = False
        self.ttt_timer = 0.0
    
    # 步骤 4：判断是否执行切换
    env_action = 0  # 默认不切换
    ttt_seconds = self.current_ttt / 1000.0  # 160 ms → 0.16秒
    
    if self.a3_condition_met and self.ttt_timer >= ttt_seconds:
        env_action = 1  # 执行切换
        self.ttt_timer = 0.0  # 重置计时器
    
    # 步骤 5：执行环境动作
    obs, reward, terminated, truncated, info = self.env.step(env_action)
```

### 3.2 状态维护

包装器需要维护以下状态：

1. **当前参数**：`current_hys`, `current_ttt`
   - 如果模型改变了参数，需要重置计时器

2. **A3 条件状态**：`a3_condition_met`
   - 记录 A3 条件是否满足

3. **TTT 计时器**：`ttt_timer`
   - 累积 A3 条件满足的时间

4. **历史信息**：`last_info`
   - 保存上一步的 RSRP 值（因为环境 step 会推进状态）

## 四、为什么需要这个转换？

### 4.1 设计目标

我们的目标是让模型**学习最优的 Hys/TTT 参数组合**，而不是直接学习"切换/不切换"。

### 4.2 优势

1. **更灵活**：模型可以根据不同场景选择不同的参数
2. **更符合实际**：实际 5G 系统就是通过设置 Hys/TTT 参数来控制切换
3. **更智能**：模型可以学习"在什么情况下用什么样的参数"

### 4.3 对比

**直接切换决策**（原始环境）：
```
模型输出：切换/不切换
→ 无法控制切换的"敏感度"
```

**参数化切换**（我们的方案）：
```
模型输出：Hys/TTT 参数
→ 根据参数自动判断是否切换
→ 可以控制切换的"敏感度"和"延迟"
```

## 五、实际运行示例

### 场景：列车从基站 A 向基站 B 移动

**时间步 1**：
- 模型输出：动作 10 (Hys=2.0, TTT=160)
- RSRP：服务=-90, 邻区=-88, ΔRSRP=2.0
- 判断：2.0 > 2.0？✗ 不满足
- 结果：不切换

**时间步 2**：
- 模型输出：动作 10 (Hys=2.0, TTT=160)（参数不变）
- RSRP：服务=-90, 邻区=-87, ΔRSRP=3.0
- 判断：3.0 > 2.0？✓ 满足，启动计时器
- 结果：不切换（计时器=0.05秒 < 0.16秒）

**时间步 3**：
- 模型输出：动作 10 (Hys=2.0, TTT=160)
- RSRP：服务=-90, 邻区=-86, ΔRSRP=4.0
- 判断：4.0 > 2.0？✓ 满足，累积计时器
- 结果：不切换（计时器=0.10秒 < 0.16秒）

**时间步 4**：
- 模型输出：动作 10 (Hys=2.0, TTT=160)
- RSRP：服务=-90, 邻区=-85, ΔRSRP=5.0
- 判断：5.0 > 2.0？✓ 满足，累积计时器
- 结果：**执行切换**（计时器=0.15秒 ≈ 0.16秒，达到 TTT）

## 六、总结

**"将 Hys/TTT 动作转换为切换决策"** 的含义是：

1. **输入**：模型输出的动作索引（0-47），代表一个 (Hys, TTT) 参数组合
2. **处理**：根据这些参数和当前的 RSRP 值，判断是否满足切换条件
3. **输出**：转换为环境可执行的简单动作（0=不切换，1=切换）

这样，模型就可以通过选择不同的 Hys/TTT 参数来控制切换行为，而不是直接决定是否切换。

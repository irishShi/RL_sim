## 面向你当前设定（SINR 代理奖励、50 ms step、乒乓窗 1s、TTS=1s）的系统性优化建议方案

### 1）先把“评价闭环”做扎实：别只看平均 SINR

你用 SINR 作为奖励代理是可行的，但要避免两个常见问题：

- **切换中断对奖励的影响不够“硬”**（RL 可能仍会为了瞬时 SINR 提升而频繁切换）；
- **不断线目标没有被明确量化**（只看平均 SINR 会掩盖深衰落与中断）。

建议你在仿真输出里固定报一组“层级 KPI”，并用它驱动后续代码优化与对比：

1. **可用性（最高优先级）**
   - Outage time ratio：
     - outage 条件：$SINR < \gamma_{\text{out}}$ 或处于切换中断 50 ms
     - 建议 $\gamma_{\text{out}}$ 起点：-6 dB（再扫 -8/-4）
   - Outage events：连续 outage ≥ $T_{\text{out}}$ 记一次（建议 200 ms=4 step，再扫 100/300ms）
2. **切换开销**
   - HO 次数（每分钟/每公里都可以，至少一个）
   - 乒乓率（你已用 1s 窗口，保留）
   - 中断总时长 = HO 次数 × 50 ms（非常直观）
3. **信号质量/吞吐代理**
   - 平均 SINR
   - 5% 分位 SINR（比平均更能体现“不断线”体验）
   - （可选）SINR 低于某门限的时间占比，如 $P(SINR<-3\,\text{dB})$

> 这样你后面所有“优化”都能回答：是否真的更不断线？是否真的更少切换？在此基础上 SINR 是否更好？

------

## 2）你现在的 TTS=1s 很关键：建议把它纳入“设计变量/敏感性分析”

你已经设置“切换后 1 秒禁止再次切换”，这对高铁非常合理（1 秒 83 m）。但它也会带来副作用：如果切到一个并不好的小区，1 秒内无法纠正。

所以建议你不要把 TTS 当成固定“拍脑袋参数”，而是系统性地做一组敏感性实验（不需要改 RL 结构）：

- TTS ∈ {0.5 s, 1.0 s, 1.5 s}（对应 42 m / 83 m / 125 m）
- 对每个 TTS，报告上面那组 KPI（尤其 outage 与 HO 次数）

目的：证明你选 1.0 s 的合理性，或发现更优折中点。审稿人非常吃这一套。

------

## 3）50 ms step + 用瞬时 SINR 作为奖励：建议加“测量滤波/状态特征增强”，提升稳定性与泛化

你现在每 50 ms 采一次 SINR，瞬时波动会让策略学得很“追噪声”。你虽然用 TTT、TTS 抑制了部分乒乓，但 RL 仍可能在边界区域做不稳定动作。

### 3.1 推荐加一个轻量的 SINR/差值滤波（不改框架，收益很大）

在进入决策/判断前，对关键测量做 IIR 平滑（系统级等价于 L3 滤波）：

- 对服务/候选 SINR 各自滤波，或只滤波差值 $\Delta\gamma=\gamma_b-\gamma_a$
- 等效时间常数建议 100–200 ms（2–4 step 量级）

你会看到：

- 乒乓率下降
- “无意义切换”减少
- 同等 outage 下平均 SINR 可能略升（因为少了中断）

### 3.2 状态里加入“历史信息”，减少仅靠瞬时 SINR 做反应

即使不改算法主体，也建议给 RL state 增加：

- 最近 $n$ 个 step 的 SINR 均值/斜率（n=3–5，即 150–250 ms）
- 当前是否处于 TTT 计时/是否处于 TTS 禁止窗口（很重要）
- 最近一次切换距离现在的时间

这些都是系统级“必需信息”，否则策略在同样 SINR 下无法区分“刚切完”和“稳定驻留”。

------

## 4）把“切换是否值得”显式体现在 reward/评估中（即便你仍用 SINR 代理）

你目前 reward 直接用 SINR，会隐含鼓励“只要能瞬时更高就切”，而切换损失仅体现在 50 ms 中断那一步。对 RL 来说，这个惩罚可能不够，尤其当切换带来的 SINR 提升持续较长时。

### 4.1 建议做一次 reward 的“结构化消融”，找稳定版本

你不一定要彻底改 reward，但建议至少对比 2–3 种 reward 设计，选一个最稳的：

- **R0（当前）**：$r_t = SINR_t$
- **R1（加入切换惩罚）**：$r_t = SINR_t - \lambda_{ho}\cdot \mathbf{1}_{HO}$
   $\lambda_{ho}$ 可从“50ms 中断等效损失”标定（见下）
- **R2（加入 outage 强惩罚）**：
   $r_t = SINR_t - \lambda_{out}\cdot \mathbf{1}_{SINR<\gamma_{out}} - \lambda_{ho}\cdot \mathbf{1}_{HO}$

标定建议（让量纲对得上）：

- 你的中断 50 ms 相当于该 step 的 SINR 直接被置为某个很低值（或吞吐为 0）。
- 你可以用经验方式：让“多一次切换”的代价大致等于“连续 1 秒 SINR 提升 1–2 dB 的收益”，这样策略才会真正珍惜切换次数。实际数值通过扫 $\lambda_{ho}$ 找 Pareto 前沿。

> 注意：即便你不用于训练，也可以把 R1/R2 当作“离线评分函数”，用于策略挑选与对比，结果会更有解释力。

------

## 5）把 TTT/H 输出落到 50 ms 网格：减少实现歧义 + 提升可复现

你每步 50 ms 决策一次，建议强制：

- TTT = k × 50 ms（k=0..N）
- H 离散到 0.5 dB 或 1 dB 档

并在论文/报告里写清楚“动作量化规则”。这样你做对比时更公平、也更像工程实现。

------

## 6）做“实验矩阵”而不是零散试验：用 Pareto 曲线展示你要的折中

你现在目标是三件事：不断线（outage）、少切换（HO/PPR）、SINR 高（平均/分位）。最适合的展示方式是 **Pareto**。

建议你固定一套场景（轨迹、基站布局、阴影衰落随机种子集合），然后跑下面矩阵：

### 6.1 必做对照（baseline）

1. 固定 H/TTT（工程常用值）+ TTS=1s
2. 贪心最强 SINR（每步选最强，配合你的 TTS）
3. RL（你的方法）

### 6.2 敏感性（每项只扫 2–3 个点就够）

- TTS：0.5/1.0/1.5 s
- $\gamma_{out}$：-8/-6/-4 dB
- $T_{out}$：100/200/300 ms
- （可选）测量滤波时间常数：100/200 ms

输出图建议：

- 横轴 HO 次数/公里，纵轴 outage time ratio（或 outage events），点的颜色表示平均 SINR 或 5% 分位 SINR
   你会得到非常直观的“少切换 vs 不断线 vs SINR”的折中曲线。

------

## 7）关于“切换成功率”的位置：在你这种简化系统级里，把它降级为辅助指标

在你不建模协议失败的情况下，HSR 很容易变成“你怎么定义都行”。建议策略是：

- 论文主结论用：outage（不断线）+ HO/PPR（少切换）+ SINR（质量）
- HSR 作为辅助：定义为“切后稳定可用率”（例如切后 200 ms 内 SINR 不低于 $\gamma_{out}$ 的比例），用来说明“切换质量”，但不要把它当唯一 KPI。

------

### 你现在最值得做的三项“代码级优化”（投入小、产出大）

1. **加入 outage/RLF 抽象（$\gamma_{out},T_{out}$）并把切换中断计入 outage**
2. **测量滤波 + 状态加历史特征**（显著降低追噪声与乒乓倾向）
3. **reward/评分加入 HO 与 outage 惩罚的消融对比 + 画 Pareto**（让“少切换优先”的目标真正落地）

如果你把你目前 SINR 的数值范围（大致分布，比如均值/方差或典型区间）和你 RL 动作空间（H、TTT 的范围）告诉我，我可以进一步给出更具体的 $\gamma_{out}$、$\lambda_{ho}$、滤波系数、TTT 档位数量等推荐，使你的敏感性扫描更“少而精”。

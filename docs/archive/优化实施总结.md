# 基于优化建议的系统性改进总结

## 一、已实施的优化项

### 1. ✅ Outage/RLF抽象完善

**实现内容：**
- 支持连续outage事件检测（T_out阈值）
- 切换中断期间自动计入outage
- 配置参数：
  - `sinr_outage_db`: -6.0 dB（可扫-8/-6/-4）
  - `T_out_s`: 0.2秒（200ms，可扫100/200/300ms）

**代码位置：**
- `envs/train_ho_env.py`: step方法中的outage事件检测逻辑
- `configs/default_env_config.yaml`: 新增配置项

### 2. ✅ Reward结构化消融（R0/R1/R2）

**实现内容：**
- **R0（当前）**：`r_t = SINR_t`（仅SINR）
- **R1（加入切换惩罚）**：`r_t = SINR_t - λ_ho * 1_{HO}`
- **R2（加入outage强惩罚）**：`r_t = SINR_t - λ_out * 1_{SINR<γ_out} - λ_ho * 1_{HO}`

**配置参数：**
- `reward_type`: "R2"（可选"R0"/"R1"/"R2"）
- `lambda_ho`: 2.0（切换惩罚系数）
- `lambda_out`: 15.0（Outage惩罚系数）

**代码位置：**
- `envs/train_ho_env.py`: `_compute_reward`方法

### 3. ✅ 测量滤波增强

**实现内容：**
- 对SINR差值（ΔSINR = SINR_neig - SINR_serv）进行IIR滤波
- 等效时间常数100-200ms（2-4步）
- 滤波后的ΔSINR可用于决策，减少噪声影响

**配置参数：**
- `enable_delta_sinr_filter`: true
- `delta_sinr_filter_alpha`: 0.7（IIR滤波系数）

**代码位置：**
- `envs/train_ho_env.py`: step方法中的SINR差值滤波逻辑

### 4. ✅ 状态特征增强

**实现内容：**
- 历史SINR统计（最近5步，250ms）：
  - `sinr_mean_db`: 平均SINR
  - `sinr_slope_db`: SINR斜率（趋势）
- TTS状态信息：
  - `in_tts_window`: 是否处于保护窗口
  - `time_since_last_ho`: 距离上次切换的时间
- 滤波后的SINR差值：
  - `delta_sinr_filtered_db`: 滤波后的ΔSINR

**代码位置：**
- `envs/train_ho_env.py`: step方法中的info字典
- `models/observation_builder.py`: 可在构建观测时使用这些特征

### 5. ✅ TTS支持距离定义

**实现内容：**
- 支持两种模式：
  - **时间模式**：`TTS_mode = "time"`，使用`T_guard_s`（秒）
  - **距离模式**：`TTS_mode = "distance"`，使用`T_guard_m`（米）
- 高铁场景推荐使用距离模式（更直观）

**配置参数：**
- `TTS_mode`: "time"（可选"time"/"distance"）
- `T_guard_s`: 1.0秒（时间模式）
- `T_guard_m`: 50.0米（距离模式）

**代码位置：**
- `envs/ho_logic.py`: `can_handover`方法支持距离模式
- `envs/train_ho_env.py`: step方法中传入位置参数

### 6. ✅ 层级KPI统计

**实现内容：**
- **可用性（最高优先级）**：
  - `outage_time_ratio`: Outage时间占比
  - `outage_events`: Outage事件数（连续outage >= T_out记一次）
- **切换开销**：
  - `ho_count`: 切换次数
  - `ho_per_km`: 切换次数/公里
  - `ping_pong_count`: 乒乓切换次数
  - `ping_pong_ratio`: 乒乓率
  - `interruption_total_time`: 中断总时长
- **信号质量/吞吐代理**：
  - `sinr_mean_db`: 平均SINR
  - `sinr_p5_db`: 5%分位SINR（比平均更能体现"不断线"体验）
  - `sinr_p95_db`: 95%分位SINR
  - `sinr_below_minus3db_ratio`: SINR低于-3dB的时间占比

**代码位置：**
- `envs/train_ho_env.py`: 
  - `_update_kpis`: 每步更新KPI
  - `_compute_final_kpis`: episode结束时计算最终KPI
  - step方法的info字典中包含最终KPI（episode结束时）

### 7. ✅ TTT量化

**实现内容：**
- 确保TTT是50ms的倍数（与时间步长对齐）
- 减少实现歧义，提升可复现性

**配置参数：**
- `ttt_quantize_to_50ms`: true

**代码位置：**
- `envs/train_ho_env.py`: step方法中的TTT量化逻辑

## 二、配置示例

### 完整配置示例（configs/default_env_config.yaml）

```yaml
# Outage阈值和RLF配置
sinr_outage_db: -6.0            # SINR outage阈值（dB），建议起点-6dB，可扫-8/-6/-4
T_out_s: 0.2                    # 连续outage持续时间阈值（秒），建议200ms=4步，可扫100/200/300ms

# Reward设计（支持R0/R1/R2消融）
reward_type: "R2"               # R0=仅SINR, R1=SINR+HO惩罚, R2=SINR+HO+Outage惩罚
lambda_ho: 2.0                   # 切换惩罚系数（用于R1/R2）
lambda_out: 15.0                 # Outage惩罚系数（用于R2）

# 测量滤波增强
enable_delta_sinr_filter: true  # 是否启用SINR差值滤波
delta_sinr_filter_alpha: 0.7    # SINR差值IIR滤波系数

# TTS配置（支持时间和距离两种模式）
TTS_mode: "time"                # "time"=按时间, "distance"=按距离
T_guard_s: 1.0                   # 切换保护时间（秒），用于time模式
T_guard_m: 50.0                  # 切换保护距离（米），用于distance模式

# TTT量化（确保TTT是50ms的倍数）
ttt_quantize_to_50ms: true       # 是否将TTT量化到50ms网格
```

## 三、使用建议

### 1. 敏感性实验矩阵

建议按以下参数进行敏感性扫描：

- **TTS**: {0.5s, 1.0s, 1.5s} 或 {25m, 50m, 75m}（距离模式）
- **γ_out**: {-8dB, -6dB, -4dB}
- **T_out**: {100ms, 200ms, 300ms}
- **Reward类型**: {R0, R1, R2}
- **滤波时间常数**: {100ms, 200ms}（对应alpha 0.6-0.8）

### 2. Pareto曲线展示

建议输出以下对比图：
- 横轴：HO次数/公里
- 纵轴：Outage time ratio（或Outage events）
- 颜色：平均SINR或5%分位SINR

### 3. 实验对照

必做对照（baseline）：
1. 固定H/TTT（工程常用值）+ TTS=1s
2. 贪心最强SINR（每步选最强，配合TTS）
3. RL（你的方法）
